# Deutsch Lernspiel

Інтерактивна вебгра українською для німецьких слів A1–A2. Працює на телефоні, планшеті та комп’ютері. Початковий урок містить 12 демонстраційних слів із перевіреними прикладами.

## Як випробувати на планшеті

Найзручніше — опублікувати статичний сайт на GitHub Pages. Хмарна машина розробки сама по собі не є публічним сайтом.

1. Збережіть створені файли в GitHub у гілку `main` (commit і push).
2. У репозиторії відкрийте **Settings → Pages → Source → GitHub Actions**. Для приватного репозиторію доступність Pages залежить від тарифу GitHub.
3. Відкрийте **Actions → Publish game to GitHub Pages → Run workflow**. Workflow запускається лише вручну.
4. Після успішного завершення відкрийте адресу з кроку **Deploy** на планшеті у Safari або Chrome. За стандартного налаштування адреса буде `https://nataliia-lernen.github.io/deutsch-lernspiel/`, але вона запрацює лише після публікації.
5. Натисніть **Тренувати обрані уроки** або **Почати швидке тренування**. Для власного списку оберіть **Додати урок**.

Альтернатива: зберіть `npm run prepare:ocr && npm run build` і завантажте папку `dist` на будь-який HTTPS-хостинг статичних сайтів. Сервер застосунку й секретні ключі для базової гри не потрібні.

Для локальної розробки на власному комп’ютері:

```bash
npm ci
npm run prepare:ocr
npm run dev
```

Планшет і комп’ютер мають бути в одній Wi-Fi мережі. Відкрийте на планшеті мережеву адресу, яку Vite надрукує після `Network` (порт 5173). Цей спосіб стосується власного комп’ютера, а не віддаленої хмарної машини. Деякі браузерні можливості на звичайному HTTP можуть бути обмежені; для постійного використання оберіть HTTPS-сайт.

## Що вміє гра

- Бібліотека власних уроків без програмного ліміту кількості; фактичний обсяг залежить від пам’яті браузера/хмарної бази. Вибирайте кілька карток, щоб змішати уроки.
- Ручна таблиця слів, вставлення списку, кілька фото за один раз з перевіркою та редагуванням. Роздільники: `—`, `–`, `;`, `=`, табуляція або дефіс із пробілами.
- Переклад в обидва боки, артиклі, самостійне написання та змішаний режим. Бали й прогрес. В артиклевому режимі тренуються лише слова з указаним артиклем.
- **Не знаю — поясни слово** показує переклад, приклад і пояснення, якщо вони внесені. Приклади й розклад для демослов підготовлено вручну; гра не генерує неперевірені пояснення. Для власного слова їх можна додати в розділі «Приклад і пояснення» під час створення уроку. За відсутності прикладу гра прямо про це повідомляє.
- Помилка або «Не знаю» додає слово до складних. Три правильні відповіді поспіль переводять його до вивчених. Повторення через 1, 2, 4, 8, 16, далі 30 днів після успішних відповідей. Нова помилка скидає серію.
- Швидкий режим на 10 хвилин, у налаштуванні тренування можна обрати 15 хвилин або заняття без таймера. Відповіді зберігаються одразу, зокрема після дострокового завершення.
- Локальне збереження, експорт і відновлення JSON-копії. Відновлення об’єднує уроки та новіший прогрес.

## Фото: можливості та обмеження

Використовується Tesseract.js із німецькою й українською мовними моделями. Платний OCR-сервіс або API-ключ не потрібний. Розпізнавання виконується на пристрої; фото до зовнішнього OCR-сервісу не передаються. Перший запуск потребує інтернету для завантаження коду, WebAssembly та моделей. Код, шрифти та моделі завантажуються з самого сайту, без сторонніх запитів під час гри. Підготовчий скрипт завантажує відкриті моделі з `raw.githubusercontent.com`, а код — із залежностей npm. Фото до 20 МБ кожне; на планшеті краще обробляти кілька невеликих чітких фотографій.

Розпізнаний текст з’являється в полі списку. Виправте його, розташуйте кожну пару в окремому рядку `der Bus — автобус`, натисніть **Перенести список у таблицю**, перевірте артиклі й переклади та збережіть урок. OCR не перекладає: якщо на фото немає українських перекладів, їх потрібно вписати. Колонки, російські переклади, рукопис, тіні та розмиття потребують ручного виправлення. Це допоміжне розпізнавання, а не гарантований автоматичний імпорт складних сторінок.

## Автоматична синхронізація між пристроями

Базова гра вже працює без хмари. Для справжньої синхронізації потрібно один раз створити власний проєкт Supabase:

1. Створіть проєкт на `supabase.com`.
2. Відкрийте SQL Editor і виконайте файл [supabase/schema.sql](supabase/schema.sql) один раз. Він створює таблицю, політики доступу лише до даних авторизованого користувача й захист від запису старіших даних.
3. У Authentication увімкніть Email/Password. У URL Configuration задайте адресу опублікованої гри як Site URL для підтвердження email.
4. Скопіюйте **Project URL** та **publishable / anon key**. Це публічні параметри клієнта; ніколи не використовуйте `service_role` / secret key.
5. У грі відкрийте **Налаштування**, введіть ці два параметри, натисніть **Підключити**, зареєструйтеся й підтвердьте email, якщо Supabase цього вимагає. Потім увійдіть.
6. На другому пристрої відкрийте ту саму гру, введіть ті самі параметри й увійдіть з тим самим email і паролем.

Синхронізація відбувається після змін, раз на 30 секунд і після повернення інтернету, поки вкладка відкрита. Кнопка **Синхронізувати зараз** показує результат або помилку. Час на пристроях має бути правильним. Різні слова й уроки об’єднуються за ID. Для одного запису зберігається новіша версія; одночасні відповіді на те саме слово на різних пристроях не підсумовуються. Фото в хмару не зберігаються — лише слова та результати. Через ліміт відповіді Supabase читання використовує сторінки по 500 записів.

Без підключеного та перевіреного Supabase синхронізація не працює. Вхід/вихід не видаляє локальні дані; у спільному браузері ними користуються всі. Не очищайте дані браузера без резервної копії. Зміна домену сайту створює окреме локальне сховище — використовуйте експорт або хмару.

## Розробка та перевірки

Потрібні Node.js 22.12+ або 24 LTS та npm. У хмарній машині за потреби додайте `--cache /tmp/deutsch-npm-cache` до npm-команд, якщо домашній каталог недоступний для запису.

```bash
npm ci
npm run prepare:ocr
npm test
npm run build
npm run dev
```

В іншому терміналі, з установленим Chromium:

```bash
CHROMIUM_PATH=/usr/bin/chromium node tests/browser.mjs
CHROMIUM_PATH=/usr/bin/chromium node tests/ocr.mjs
```

Браузерні перевірки очікують сервер на порту 5173. `tests/browser.mjs` перевіряє вузький екран, тренування, складні слова, створення уроку, збереження після перезавантаження та написання відповіді. `tests/ocr.mjs` розпізнає справжнє тестове зображення з німецькими та українськими словами; використовує підготовлені локальні моделі OCR. Для іншого шляху до Chromium задайте `CHROMIUM_PATH`.

Стек: Vite, звичайний JavaScript, CSS, Tesseract.js, Supabase JS. Немає офлайн-режиму, генерації пояснень ШІ чи необхідності в платному API. Розгортання й перевірка реальної синхронізації потребують налаштувань власника.
